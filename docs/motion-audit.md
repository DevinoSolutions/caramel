## Tokens PR

Tailwind is v3, so tokens go as CSS custom properties plus matching `theme.extend`.

### Where

1. `apps/caramel-app/src/styles/globals.css`, in a `:root` block near the top (after the `@tailwind` directives):

```css
:root {
    --motion-dur-fast: 120ms;
    --motion-dur-base: 180ms;
    --motion-dur-slow: 240ms;
    --motion-ease-out: cubic-bezier(0.16, 1, 0.3, 1);
}
```

2. `apps/caramel-app/tailwind.config.ts` `theme.extend`: `transitionDuration: { fast: 'var(--motion-dur-fast)', base: 'var(--motion-dur-base)', slow: 'var(--motion-dur-slow)' }` and add `'motion-out': 'var(--motion-ease-out)'` to the existing `transitionTimingFunction` block (which already holds `caramel`; keep it, the hero uses a near-identical curve and must not change). Plus the shared keyframes (`motion-fade-in`, `motion-fade-up`, `motion-check-in`) under `keyframes`/`animation` so spots 1, 5, 6, 7 reuse them. Because there is no `tailwindcss-animate`, bare `animate-in` classes must not be used.
3. The global reduced-motion net, appended to `globals.css` (exactly the brief's rule; do not reuse the popup's `!important` variant, whose `0.001ms` and scroll-behavior lines are specific to the popup):

```css
@media (prefers-reduced-motion: reduce) {
    *:not(.animate-spin),
    *::before,
    *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
    }
}
```

Interaction to verify in that PR: the net also hits `.hero-enter` (already `animation:none` under reduce) and the theme-toggle SVG (already gated), so no conflicts; the `Loader` spinner is exempted by `.animate-spin`; sonner animations are zeroed under reduce, which is the desired behaviour.

### MotionConfig

Yes, add `<MotionConfig reducedMotion="user">` (imported from `framer-motion`) in `apps/caramel-app/src/app/providers.tsx`, directly inside `<LazyMotion features={domAnimation}>` (line 105) so it wraps `PostHogClientProvider` and everything below. Today nothing opts framer into reduced motion globally (only components that import `src/lib/reducedMotion.ts`), so every `whileInView`/`animate` translate currently runs for reduce users. `MotionConfig` is a few hundred bytes and does not change the `domAnimation` bundle. Caveat from the existing comment in `reducedMotion.ts`: `initial` is read at mount, so a reduce visitor still gets the SSR-serialised initial offset; `MotionConfig` does not change that and nothing here should try to.
