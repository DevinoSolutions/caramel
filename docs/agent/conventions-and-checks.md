Root-file allowlist → `tests/unit/repo-integrity.test.ts`. Coupons SQL lives only in `src/lib/couponsRepo.ts` (never inline in a route/page) → exercised by the integration suite (`tests/integration/coupons-read.itest.ts`, `coupons-write.itest.ts`, `ingest-catalog.itest.ts`, `bridge-sync.itest.ts`, `extension-oauth-session.itest.ts`; `pnpm --filter caramel-app test:integration`) running the real queries against a live app Postgres — this REPLACED the deleted structural drift gate (`check:coupons-schema`, `tests/drift/coupons-schema.drift.ts`, `vitest.drift.config.ts`, `EXPECTED_COLUMNS`, `couponsQueryProbes`, all removed in W4); every read is still zod-parsed by `parseCouponRows` (schema drift throws loudly). Secrecy forward-rule INVERTED (W3): the app now LEGITIMATELY owns `coupons`/`sources`/`store_configs` in `prisma/schema.prisma`; what stays out is the scraper's PIPELINE-INTERNAL machinery (`verification_stores`, `store_verification_configs`, `verification_*`, `agent_*`/`scraper_*`) → enforced by `tests/unit/prisma-schema-secrecy.test.ts` (map-target based: bans those @@map/@map targets, allowlists `verification_message`/`verification_tokens`). Phase-3 enforcement: the Chrome and Firefox manifests come from ONE `wxt.config.ts` (the old hand-kept twins and their `manifest-sync.test.ts` are gone) and their semantic parity is gated by `apps/caramel-extension/scripts/parity-harness.mjs` (`test:parity`; frozen goldens + a shrink-only allowlist of deliberate per-browser differences, NOT to be forced together); extension e2e — real Chromium loading a patched temp copy of the extension against the local app with a seeded verified user → `checks-extension.yml`'s `extension e2e` job (PR-only, DB-backed); real-login success e2e + the seed-user pattern (real `/api/auth/sign-up/email` + an announced test-only `emailVerified` DB flip, `@prisma/client` imported LAZILY inside the fn so `e2e-push` collection survives without a generated client) → `e2e/auth-flows.spec.ts` + `e2e/support/seed-user.ts`; the extension OAuth mint re-auth path against real better-auth constraints → `tests/integration/extension-oauth-session.itest.ts`. The e2e suite runs in TWO contexts — hermetic (`e2e-pr`/local: fresh migrated+seeded Postgres, `DATABASE_URL` set) and deployed (`e2e-push`: live dev site, NO `DATABASE_URL`, no generated prisma client, REAL catalog data) — so any spec asserting specific DB content or touching the DB MUST gate on `test.skip(!process.env.DATABASE_URL, …)` and MUST NOT import `@prisma/client` at module top level (collection runs in both); deployment-safe assertions (page shell, generic content presence) stay ungated. The client IP is read ONLY through `src/lib/clientIp.ts` (`CLIENT_IP_HEADERS`: CF-Connecting-IP first, because Traefik's X-Real-IP is the Cloudflare edge; `readClientIp`), which feeds both `getClientIp` (our rate limiter) and Better Auth's `advanced.ipAddress.ipAddressHeaders` (#256) → eslint `caramel/no-raw-client-ip-header` (`tools/eslint-rules/no-raw-client-ip-header.mjs`, tested by `pnpm test:eslint-rules`) bans naming `cf-connecting-ip`/`x-real-ip`/`x-forwarded-for` anywhere else under `src/`, and `tests/unit/better-auth-client-ip.test.ts` pins that auth.ts uses the shared order. Unenforced (memory only): new routes must use `withRoute`; env reads only via the env modules; new `.eval.ts` stays out of the unit glob.

## Paid fallback through the Devino proxy → its checks

Added 2026-10-15, not part of the 2026-10-07 move. All files are under `apps/caramel-app/tests/unit/`. No request sends the paid-fallback headers today (both LLM routes are guest-reachable); a future signed-in caller adds its own wiring and trace tests here.

- The paid-fallback key could only ever reach `https://proxyai.devino.ca`, the wait stays at or under 12 s, and a malformed value refuses boot without being printed → `paid-fallback-key-reaches-only-the-devino-proxy-with-a-capped-wait.test.ts` (host, wait and predicate cases) + `paid-fallback-settings-never-reach-evals-or-e2e-and-bad-ones-refuse-boot.test.ts` (the real env schema; error and console output).
- Guests never carry the key: the real `chat()` and `POST /api/classify-cart`, with the key set, send no `X-ORF-Fallback-*` header, one classify is one request, and the key reaches no log sink → `guest-llm-routes-never-send-the-paid-fallback-key.test.ts` (fetch stubbed at the network edge).
- Evals and E2E never carry the paid-fallback settings → `paid-fallback-settings-never-reach-evals-or-e2e-and-bad-ones-refuse-boot.test.ts` (loads the real `vitest.eval.config.ts`, parses `playwright.config.ts` and requires the three blanks in the web server env).
- The request rules a future signed-in caller must follow: `fetchWithoutRedirects` fails on a 307 to another host, which never sees the key, and a paid path's deadline floor is 20 s → `paid-fallback-fetch-refuses-redirects-and-paid-paths-get-20-seconds.test.ts` (two real local servers and the real fetch).
- A key set off the proxy is never sent and warns once without its value → `paid-fallback-warns-once-when-the-key-cannot-reach-the-proxy.test.ts` (the real env reader).
